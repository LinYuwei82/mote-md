# mac/clipboard 合并前核对清单（macOS 机器用）

## 前提

1. 在 macOS 机器上 checkout 本分支：`git checkout mac/clipboard`。
2. 确认历史：`git log -3` 应依次看到 `aa561f9`、`64c8780`、`78f9b79`（`aa561f9` 修复空段落块被当作可复制内容；`64c8780` 复制补 HTML、失败提示与块外粘贴兜底；`78f9b79` 右键菜单加入剪切/复制/粘贴）。
3. 本清单只覆盖 **Mac 侧无法在 Windows 验证**的部分。Windows 侧已实测：Ctrl+X 剪切（纯文本 + `HTML Format`、空选区提示、落盘、连续剪切、剪后粘贴）、图片粘贴与资源管理器拖放。Mac 侧不需要重复这些。

建议全程以 `MOTE_KEYLOG=1` 启动，按键与页面桥接的日志会打到 stderr，便于失败时取证。

## 第一项：复制保留格式

**目的**：确认 Cmd+C 复制时同时写入富文本（`public.html`）与纯文本，且富文本里没有 Mote 的内部标记。

### 步骤

1. 用 Mote 打开一篇文章，正文里同时包含：标题（`#`/`##`/`###` 至少各一个）、无序列表、有序列表、普通段落，最好再带一处行内代码与一个链接（可直接用 `docs/DECISIONS.md` 当样本）。
2. 从标题开始拖选，跨过列表与段落，选中多块内容。
3. `Cmd+C`。
4. 粘到以下两个目标，分别观察：
   - **TextEdit 富文本**：新建文稿后直接 `Cmd+V`（不要先「转换为纯文本」）；或 Mail 的新邮件正文里 `Cmd+V`。
   - **TextEdit 纯文本**：新建文稿，菜单「格式 → 转换为纯文本」，再 `Cmd+V`。

### 期望结果

- 富文本目标：标题层级保留（h1/h2/h3 的样式差异可见）、列表保留项目符号或编号、段落分隔正常。
- 富文本目标：**不出现** `#`、`- `、`1. `、`*`、反引号、`[](...)` 这类 Markdown 源码前缀。
- 富文本目标：没有零宽字符残留（不出现莫名的空位、方框、异常光标停顿；行内标记的小标签文字也不应被带出）。
- 纯文本目标：只得到干净文本——标题不带 `#`、列表项不带 `- `、行内代码不带反引号、链接只剩可见文字（Mote 现有行为）。
- 若需要更严格地查零宽字符：把纯文本结果粘到终端里执行 `cat -v` 或 `hexdump -C`，确认没有 `e2 80 8b`（U+200B）等标记残留。

> 反向检查：粘到纯文本编辑器应只得到干净文本；若纯文本里出现 `#`、`- `、`.mk` 之类的内容，或富文本里出现源码前缀，都判不通过。

## 第二项：空选区提示

**目的**：确认没有可复制/可剪切的内容时只给提示，既不覆盖剪贴板，也不删内容。

> 注意：本项中的 copy/cut 事件分支是 `aa561f9` 在 `resources/web/editor.js` 新加的，Windows 侧只覆盖了宿主 `clipboardCopy` 路径，macOS 的原生 `copy:`/`cut:` 分支**本机未实测**。

### 步骤

先准备基线：复制一段已知文本（例如「基线内容」），确认 `Cmd+V` 能粘出这四个字。

依次测试三种情况，每种都先 `Cmd+C` 再 `Cmd+X`：

1. **完全没选中**：在正文里点一下，让光标折叠（无选区）。
2. **选中一个空段落块**：找一个空行，从空行拖选（或点进空行后用 `Shift+方向键` 扩选）。
3. **选中只有空格的块**：在一个段落里连续输入几个空格成段，然后选中该块。

### 期望结果

- 状态栏出现提示：复制为「没有可复制的内容：先选中文字」，剪切为「没有可剪切的内容：先选中文字」。
- 剪贴板内容不变：三种情况做完后 `Cmd+V` 粘出的仍是「基线内容」。
- `Cmd+X` 不删除任何内容：块数不变、正文不变、窗口标题不出现 `*`（不产生未保存改动）。

- 截图：状态栏当时的文字。

## 第三项：块外粘贴

**目的**：确认光标落在正文块外（最后一块下方的空白区）时，粘贴仍能落进正文，且图片粘贴链路不受影响。

### 步骤

1. 打开一篇已有内容的文档，把光标点到**最后一块下方的空白区**（编辑区底部、正文之外）。
2. 剪贴板里放一段纯文本，`Cmd+V`。
3. 观察是否自动补出一个段落块并在其中插入文本。
4. `Cmd+S` 保存，关闭文档再重新打开，确认这段文字仍在。

### 期望结果

- 粘贴后自动新增一个段落块，文本在其中，光标位于插入内容之后。
- 保存后磁盘文件包含该段文字；重开文档内容不丢。
- 若光标确实无法落在块外，允许判「不适用」，但要记录实际现象（例如点击空白区后光标仍进入最后一块），不要直接判通过。

> 反向检查（图片粘贴）：用 `Cmd+Ctrl+Shift+4` 截一张图到剪贴板，光标放回正文里 `Cmd+V`。期望图片落盘到当前文档同目录的 `assets/`，正文插入 `![](assets/paste-<日期>-<时间>.png)`，状态栏提示「已保存图片：assets/...」。若文档尚未保存，则期望提示「图片未插入：当前文档还没有保存位置，请先保存 .md 文件」，且不写入任何位置。

- 现象：粘贴后块是否新增、文本落在哪里、保存后重开是否还在；图片场景记录 `assets/` 是否出现新文件、正文引用是否插入。
- 截图：粘贴前后与重开后的正文、状态栏。

## 已知不确定点

- `macwebview.mm` 本轮**未改**。macOS 的复制/剪切仍走 AppKit 的 `copy:`/`cut:` 响应链，页面 `copy` 事件负责产出 `text/html`；这条链路依赖 WKWebView 的原生行为，以及 Qt 对 `QClipboard → NSPasteboard` 的映射。这两点目前只是**推断**，没有在 macOS 上实测过。
- 第二项的 copy/cut 事件分支同样只做了代码审查与 Windows 侧的同逻辑验证，macOS 未实测。
- 如果第一项失败（粘到富文本目标只得到纯文本，或格式错乱），最可能的修法是给 macOS 补一个显式的 `NSPasteboard` 写入（同时写 `public.html` 与 `public.utf8-plain-text`），而不是继续依赖 WebKit 的默认映射。
