# mote 空行折叠修复 · 手工验证清单

**适用改动**：让块与块之间的空行数量在保存后保持原样（此前固定拼 `\n\n`，连续多个空行会被归并）。
**状态**：改动已落地——core 层纯函数 `core/block_layout.*`（`68fa133`）与前端 `resources/web/editor.js`（`4bb2046`）。Windows 上已用 7 组文档跑「载入 → 保存」字节级往返，全部一致；本清单余下的交互项（选区、查找、undo/redo、双平台）仍未手工验证。
**依据**：[`WEBVIEW-ARCHITECTURE.md`](WEBVIEW-ARCHITECTURE.md) 中「MVP 对空行数量有归并」的已知限制。
**风险点**：选区映射、查找高亮、undo/redo 恢复原先都假设「每块之间恰好 2 个字符」（`resources/web/editor.js` 的 1614 / 1719 / 1749 / 2553 / 4898 / 4931 六处）。这些位置已改为按实际间隔累加（`blockStartOffset` / `gapBefore` / 快照携带 `gaps`），仍须按第 4 组逐项确认没有错位。

---

## 0. 准备

| 项 | 做法 |
|---|---|
| macOS 构建 | `cmake -S native -B build-native && cmake --build build-native`，产物在 `build-native/` |
| Windows 构建 | 推送后取 GitHub Actions 的 CI 产物，或本地 `cmake -S native -B build-native -G Ninja -DMOTE_BUILD=<时间戳>` |
| 测试文档 | 新建 `blank-lines.md`，内容按下面各用例填写；另存一份副本用于比对 |
| 字节级比对 | macOS：`cat -A blank-lines.md`（行尾 `$`，空行是一行只有 `$`）；或 `python3 -c "print(open('blank-lines.md','rb').read().count(b'\n\n\n'))"` |
| 保存前后对比 | 保存前 `cp blank-lines.md before.md`，保存后 `diff before.md blank-lines.md`，期望无输出 |

**先复现旧行为（可选，用于确认测量方法有效）**：用改动前的构建（≤ 1.0.4）写「A / 两个空行 / B」保存，`diff` 应显示第三个换行被吞——这就是已修的问题。若旧构建也能保留，说明测量或版本不对，先停下核对。

## 1. 空行数量保留（核心）

- [ ] **1.1 单空行基线**：`A⏎⏎B` 保存后 `diff` 无差异
- [ ] **1.2 两个空行**：`A⏎⏎⏎B` 保存后仍为 3 个换行，界面块间距也保持更大
- [ ] **1.3 三个以上空行**：`A` + 4 个空行 + `B`，保存后换行数不变
- [ ] **1.4 文首空行**：文档以 1~2 个空行开头，保存后仍在
- [ ] **1.5 文末空行**：末尾多留 2~3 个换行，保存后数量不变（原有 `trailingNewline` 只保留 1 个，注意这是本次要扩展的部分）
- [ ] **1.6 全空文档**：只有空行的文件打开→保存，不崩溃、不留意外内容

## 2. 结构内部空行不被误切

- [ ] **2.1 围栏代码块**：代码块内连续空行保存后不变，块仍是一个整体（不被拆成多个块）
- [ ] **2.2 列表**：列表项之间夹空行，保存后列表结构与空行都保留
- [ ] **2.3 表格**：单元格为空、表格前后各有多个空行，保存后表格不被拆散
- [ ] **2.4 引用块**：`>` 行之间的空行保存后保持

## 3. 编辑路径（空行由操作产生时）

- [ ] **3.1 空行处回车拆块**：在两段之间按两次回车拆出新块，保存后为「段 / 空行 / 段」各一个空行
- [ ] **3.2 删除中间块**：删掉一段后，剩下两块之间的空行数量符合预期且不丢内容
- [ ] **3.3 块内 Shift+Enter**：段内软换行不被当成块间隔
- [ ] **3.4 粘贴多行文本**：粘贴「甲 / 空行 / 乙 / 空行 / 丙」，保存后落盘为三段、两处各一个空行
- [ ] **3.5 拖入 .md 替换**：有未保存修改时拖入文件 → 先弹保存确认；确认后新文档的空行原样保留
- [ ] **3.6 图片插入**：在含多空行的文档里插图，保存后空行数量不变

## 4. 偏移相关回归（重点，最容易出问题）

> 这组用例专门验证「每块 +2 字符」的假设被替换后没有算错位置。

- [ ] **4.1 查找高亮**：在含「A + 两个空行 + B + 两个空行 + C」的文档里查找 `C` 中的字，高亮落在正确位置（不是偏到 B 或块外）
- [ ] **4.2 跨块选区**：从 A 块中间拖选到 C 块中间，复制出的文本包含的换行数与屏幕间距一致
- [ ] **4.3 选区恢复**：跨块选中后按 Cmd/Ctrl+Z 再 Shift+Cmd/Ctrl+Z，选区回到同一位置，不跳到别块
- [ ] **4.4 undo/redo 多次**：连续编辑 5 步以上（含拆块、删块），逐步撤销再重做，块数与空行数都还原
- [ ] **4.5 块内光标**：在多个空行的文档里，把光标点到第 4 块某行中间，输入字符无跳位
- [ ] **4.6 目录（TOC）跳转**：点击目录项后滚动与高亮落在正确标题上

## 5. 已修改状态与保存基准

- [ ] **5.1 打开即未修改**：打开含多空行的文件，标题栏不显示「已修改」圆点
- [ ] **5.2 保存后圆点消失**：修改一处后保存，圆点立刻消失、不残留
- [ ] **5.3 不产生虚假修改**：只点击块进入编辑态再点出（不改内容），不应判定为已修改
- [ ] **5.4 保存基准一致**：保存后立刻再按 Cmd/Ctrl+S，`diff` 无差异（避免每次保存都追加/吞空行）

## 6. 性能与稳定性

- [ ] **6.1 大文档**：100 个块、块间 1~3 个空行，打开与保存无可感知卡顿
- [ ] **6.2 快速连续保存**：连按保存 5 次，文件内容稳定、不递增空行
- [ ] **6.3 源码模式切换**：Cmd/Ctrl+/ 在所见即所得与源码模式间来回切换 3 次，空行数量保持一致

## 7. 双平台

- [ ] **7.1 macOS**：以上 1~6 全过
- [ ] **7.2 Windows**：至少覆盖 1.1 / 1.2 / 1.5 / 2.1 / 4.1 / 4.2 / 5.1 / 5.2；CRLF 与 LF 输入结果一致
- [ ] **7.3 Windows 编码组合**：用 GBK 存的中文文档（含多空行）打开→保存，中文不乱码、空行不变

## 判定

- **通过**：1~6 全部勾选，且 `diff` 在所有保存用例中无差异；4 组无位置偏移；双平台一致
- **不通过**：任何一个 `diff` 出现空行增减，或 4.x/5.x 出现错位与虚假「已修改」
- 失败时请附：`before.md` / 保存后的文件、`diff -u` 输出、操作步骤截图

## 附：已补的自动化

「块间隔计算」已抽成 core 层纯函数：`core/block_layout.h` 的 `joinBlocks` / `measureBlockGaps` / `blockStartOffset`，`native/tests/core_tests.cpp` 的 `testBlockLayout` 覆盖：
